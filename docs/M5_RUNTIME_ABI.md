# M5 bare-metal model/runtime ABI v1

Status: **frozen before runtime implementation; portable complete-model logic
and numerical foundation pass, hardware-backed firmware entry and physical
supervisor remain unqualified**.

This ABI complements the frozen model arena and transfer ABIs. It does not relax
the M5 scope or allow an A9 operator worker. The A9 may populate this interface
only before releasing the harts, and may read it only after ownership has safely
returned. During RUN, it may observe top-level status/token transport but cannot
modify descriptors, tensors, metadata, cache, tokens or decisions.

## Arena and model identity

Device virtual memory remains `0x40000000..0x4fffffff`, with the exact `PAM5`
arena header generated by `ref/m5_arena.py`. Runtime must validate before use:

- magic `0x354d4150`, ABI 1, 64-KiB header and 256-MiB arena;
- exactly 248 array descriptors and 15 region descriptors, each 32 bytes;
- GPT-2 geometry 1024 positions, 12 layers, 12 heads, width 768 and vocabulary
  50,257;
- frozen M4 pack SHA-256
  `d2aafeffd3e4b8a134b8e48796a1b0cf8f296a3bd150b79f07e2de037fae8fd6`
  and adaptive-v3 candidate SHA-256
  `a8d80d03c1aacc8a40f0f84962acd4033f0a1afb1343fd9e1ab0e9c50d0c397d`;
- exact descriptor IDs, shapes, dtypes, 64-byte alignment, nonoverlap, model
  bounds and region permissions. Unknown/reordered/aliased arrays are rejected.

Array IDs are deterministic: embedding 0, position 1; layer `L` starts at
`2+20*L`, with `{attn.c_attn,attn.c_proj,mlp.c_fc,mlp.c_proj}` occupying four
consecutive `{tiles,scale,bias,smooth}` descriptors, then LN1 gain/bias and LN2
gain/bias. Final LN gain/bias are 242/243 and LM-head tiles/scale/bias/smooth are
244..247. Static model bytes are read-only.

The guarded region bases are fixed by the serialized layout:

| Region | Device VA | Bytes | Runtime permission |
|---|---:|---:|---|
| model | `0x40000000` | 205,340,672 | read |
| K int16 | `0x4c3d5000` | 18,874,368 | read/write |
| V int16 | `0x4d5d6000` | 18,874,368 | read/write |
| K8 int8 | `0x4e7d7000` | 9,437,184 | read/write |
| K units f64 | `0x4f0d8000` | 1,179,648 | read/write |
| work | `0x4f1f9000` | 4,194,304 | read/write |
| trace | `0x4f5fa000` | 8,388,608 | read/write |

Every adjacent guard and the unused tail remains unmapped. The cache index is
`[((layer*12+head)*1024+position)*64+feature]`; K/V are little-endian int16,
K8 is int8 and the K unit is one little-endian binary64 value per
layer/head/position. Valid cache length is committed only after a whole token
successfully completes; an errored in-flight token must not extend it.

## Provisioning command and result

The first 4-KiB work page at `0x4f1f9000` is the control block. All fields are
little-endian 32-bit words unless stated otherwise. Input tokens start at work
offset `0x1000`; generated-token output starts at `0x2000`; each has 1,024
uint32 slots. The remaining work space is a bounded runtime allocator. Firmware
must publish actual high-water bytes; exhaustion is an error, never an alias.

| Offset | Field |
|---:|---|
| `00` | magic `0x35545250` (`PRT5`) |
| `04` | ABI version 1 |
| `08` | request ID |
| `0c` | command: 1 RUN, 2 validation-only |
| `10` | prompt count, 1..1024 |
| `14` | generation count, 1..`1024-prompt_count` |
| `18` | flags: bit 0 capture checkpoints, all other bits zero |
| `1c` | deadline per transfer command, nonzero |
| `20` | state: 0 staged, 1 validating, 2 ready, 3 running, 4 done, 5 error, 6 stopped |
| `24` | stable error code |
| `28` | completed/cache-valid positions |
| `2c` | generated-token count |
| `30` | current layer |
| `34` | current operator ID |
| `38` | accepted transfer count |
| `3c` | completed transfer count |
| `40/44` | fabric cycle start/end |
| `48` | work allocator high-water bytes |
| `4c` | trace bytes valid |
| `50/54` | tensor bytes read/written modulo 2^32 |
| `58` | selected token (valid after each committed step) |
| `5c` | hart-ready bits; bit 0 hart 0, bit 1 hart 1 |
| `60` | hart-error bits |

The remaining control page must be zero. Tokens must be below 50,257. Counts,
flags, command and deadline are captured and validated before state READY. An
invalid request, position overflow, model mismatch or work-layout overflow must
leave all cache-valid positions and output tokens unmodified. State and progress
are publication points with RISC-V fences; partial tensors are never success.

## Hart roles and lifecycle

Hart 0 owns model control flow, dynamic scale/epsilon metadata, activation/KV
preparation, cache-valid publication, complete logits and lowest-ID greedy token
selection. Hart 1 exclusively owns GEMM/SFPU/transfer descriptors, route and
their IRQ acknowledgements. Hart 0 sends complete immutable jobs through the
mailbox and never writes accelerator registers. Hart 1 cannot decide model layer,
operator shape, cache validity, scale policy or tokens; it validates and executes
the job supplied by hart 0. Both roles are useful and exercised.

All dynamic float64 work uses software IEEE-754 binary64 on RV32IMC; Ibex has no
F/D extension. Conversion to integer is explicit round-to-nearest, ties-to-even,
independent of host C-library conversion mode. The implementation must qualify
soft-double multiplication/division/square root and metadata boundaries against
the immutable Python reference before model acceptance. Static f64 arrays are
metadata, not replacement floating GEMMs.

Startup is: provision owned pages/table/model/control/tokens; load and verify the
complete zero-padded firmware image under core reset; flush mappings while
aborted and drained; perform the drained cluster-IO reset; release abort, then
release harts. Completion/failure is: latch core stop; retire local and host
transactions; assert cancellation and accelerator reset; wait full translated
memory drain; only then read/validate or remap/free. Reset, deadline or ERROR
does not fabricate returned ownership. Restart repeats validation and must pass
without stale cache, mailbox, IRQ, descriptor or token state.

This ABI freezes the software-visible boundary. It does not claim the protected
supervisor, Linux allocation helper, firmware model loop or board overlay exists.
